# Convenciones visuales

| Aspecto | Convencion |
| --- | --- |
| Resolucion base | 1440 x 900 para escritorio. |
| Resolucion movil opcional | 390 x 844 solo cuando el comportamiento responsive sea relevante. |
| Relacion de aspecto | 16:10 para escritorio; vertical para movil. |
| Formato | PNG. |
| Zoom navegador | 100%. |
| Tema | Tema claro para el manual, salvo que se documente explicitamente el cambio de tema. |
| Navegador | Usar el mismo navegador en toda la serie de capturas. |
| Recorte | Recortar solo cuando mejore la lectura; conservar contexto suficiente de navegacion. |
| Numeracion | `MU-###-descripcion-corta.png`. |
| Pie de imagen | "Figura MU-###. Accion o estado mostrado." |
| Datos visibles | Solo datos ficticios o anonimizados. |
| Tokens | No mostrar tokens reales completos. |
| Correos/documentos | Enmascarar o usar dominios ficticios. |

## Anotaciones

- Usar recuadros finos y flechas solo para senalar la accion principal.
- No usar mas de dos anotaciones por captura.
- No saturar capturas con explicaciones; el texto del manual debe explicar el procedimiento.
- Mantener contraste alto y texto minimo legible.
- No generar imagenes decorativas.
- Cada captura debe ensenar una accion, estado, validacion o decision.

## Consistencia

- Mantener la misma cuenta demo para pantallas internas.
- Mantener los mismos nombres ficticios de robots cuando se muestre continuidad de un flujo.
- Evitar que el sistema operativo, barra de favoritos o notificaciones aparezcan en la captura.
- Ocultar datos sensibles antes de capturar, no despues como unica medida.
- Si una captura muestra Admin, preferir recortes que no expongan columnas completas con PII.
